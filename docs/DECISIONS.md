# Decisions

Record of decisions and why they were made. The ones marked "round" come from the question round (answer: "all defaults"). The rest were taken during implementation, picking the simplest option that meets the criteria.

On 2026-10-03 the product was renamed Neurons (I28). Rows D1 to I27 keep the names they were decided with: `repo-synapse start` is now `neu start`, `.repo-synapse/` is `.neurons/`, `?src=repo-synapse` is `?src=neurons`, `$CLAUDE_CONFIG_DIR/repo-synapse/` is `$CLAUDE_CONFIG_DIR/neurons/` and `REPO_SYNAPSE_ALLOWED_ORIGINS` is `NEURONS_ALLOWED_ORIGINS` (the old name is still accepted).

`docs/DEMO.md` was removed in 0.3.0 (round 4). Its demo prompts now live in the guide: `docs/guide.html#faq-demo` (a throwaway clone of Neurons) and `#faq-demo-small` (the repo from `scripts/make-demo-repo.sh`). I9 and I26 keep the old name.

## Question round (2026-09-30)

| # | Topic | Decision | Reason |
|---|---|---|---|
| D1 | Hook transport | `type: "http"` hooks, written by `repo-synapse start` into `<repo>/.claude/settings.local.json` and removed on exit | With the server down, a permanent HTTP hook prints a red `hook error` on every tool call (verified in the 2.1.285 binary). Installing only while the viewer runs meets criterion 8.2 without giving up HTTP latency |
| D2 | Runtime | Node >= 22.12 + TypeScript, `node:http` + `ws`, no framework | One POST route, static files and a WS upgrade do not justify a framework. `tsx` in development, `tsdown` for the bin (tsup is unmaintained) |
| D3 | View | 3D with `3d-force-graph` + bloom, Vite + TS, 2D toggle with `force-graph` | Vite guarantees a single copy of three.js for the graph and `UnrealBloomPass` |
| D4 | Scope | One repo per process, several sessions and subagents with filters | Simplicity; two repos = two processes |
| D5 | Port | `7777`, and the next free one when it is taken | Possible because `start` writes the real port into the hooks |
| D6 | External changes | Shown in dim gray, with a toggle | Telling Claude apart from everything else is part of the teaching goal |
| D7 | `bashEditDiffEnabled` | Test it in phase 0; if it arrives in the HTTP payload, `start` turns it on in the user settings and reverts it on exit | Gives exact attribution of `rm`/`mv` |
| D8 | Phase 0 | Real `claude -p` sessions with a capped budget | Real payloads from the installed version, not assumptions |
| D9 | Distribution | npm package ready, not published; used through `npm link` | Publishing is the user's call |
| D10 | Name and language | `repo-synapse`; UI and README in Spanish; code and commits in English | Round. The UI became bilingual in 0.3.0 (I40) |
| D11 | Scale | Calibrated for 5,000 files; collapse above 1,500 visible nodes | The size of the real repo was not given |
| D12 | Sound | Not implemented | Round |
| D13 | Git | Commits on `main`, no push | Round |

## Implementation

| # | Decision | Reason |
|---|---|---|
| I1 | Watcher with native `fs.watch(root, {recursive: true})`, not chokidar | chokidar 5 opens one fd per file on macOS and fails with `EMFILE` in large repos; recursive `fs.watch` uses FSEvents |
| I2 | Our own hooks are identified by the exact URL with `?src=repo-synapse` | A prefix such as `http://127.0.0.1` would delete other tools' hooks (bug documented in agent-flow) |
| I3 | `POST /hook` answers `204` with no body before processing | A text body produces a `hook error`; a JSON body could be read as a decision |
| I4 | A session is created with the first event that carries a new `session_id` | `SessionStart` does not accept HTTP hooks |
| I5 | Searches detected by classifying Bash commands | The native macOS build has no Glob/Grep tools |
| I6 | `.claude/settings.local.json` and `.repo-synapse/` go to `.git/info/exclude` when git does not ignore them | Auto-gitignore is not assumed; `info/exclude` does not touch versioned files |
| I7 | `bashEditDiffEnabled` is turned on in `~/.claude/settings.json` (or `$CLAUDE_CONFIG_DIR/settings.json`) while `start` runs, and reverted on exit, only if it was not already on | Phase 0: the field arrives in the HTTP payload but only when the key is in the user settings; in `settings.local.json` it is ignored |
| I8 | Search result paths are taken from Bash `stdout` (`path` or `path:line:` lines) and validated against the tree index | It is the only source of results in the native build; the text never leaves the server |
| I9 | Verified on 2026-10-03 with Claude Code 2.1.288 in real interactive sessions: a session opened before `neu start` picks up the hooks at once (events arrive without a restart), and after `neu stop` the same session stays open, runs a new prompt and shows no `hook error` (the hooks are removed live). The `start` notice (I31) no longer asks for a restart: it keeps it as plan B for older versions if no events arrive (since I50: `/reload-plugins` first, then the restart) | It used to be listed as unverified because `-p` cannot test it; `DEMO.md` asked to start the viewer before Claude |
| I10 | Performance measured (2026-09-30): synthetic repo with 2,000 files (2,107 nodes, 1,747 visible after collapsing), 3D view with bloom, 49 `Read` events in 5 s through `POST /hook`. Playwright Chromium with `--use-angle=metal --enable-gpu --ignore-gpu-blocklist`, renderer `ANGLE Metal Renderer: Apple M4`: **60 fps** median, 60 mean and 60 minimum. That is the `requestAnimationFrame` cap, so the real headroom does not show | `test/e2e/perf.spec.ts` only requires 30 fps when the WebGL context runs on a GPU; with SwiftShader or llvmpipe it skips and records the value |
| I11 | E2E on the real built CLI (`dist/cli.mjs`), one server per spec (live 7791, replay 7792, perf 7793) launched by `scripts/e2e/serve.mjs` on temporary repos, with a temporary `CLAUDE_CONFIG_DIR` | Test what ships, not a fake server. On exit the launcher checks that `start --no-install` touched neither the sentinel `settings.json` nor `.claude/settings.local.json` |
| I12 | The Bash `detail` is the first logical line of the command, without heredoc bodies; if the line writes files (`>`, `>>`, `tee`, `sed -i`) or runs inline code (`python -c`, `node -e`, `bash -c`...), quoted literals and the arguments of `echo`/`printf` are replaced with `…` | A Bash command can carry the content it writes (`cat > .env <<EOF`), and that text must not reach the browser or `events.jsonl` |
| I13 | `/ws` and `/hook` accept only the server's own origin (`http://127.0.0.1:<port>` and `http://localhost:<port>`) and the ones added with `REPO_SYNAPSE_ALLOWED_ORIGINS` (for example `http://localhost:5173` for `vite` in development) | A page served on another local port could read the stream or inject hooks. Vite's `rewriteWsOrigin` is not used because it lets any origin through |
| I14 | `start` always adds `.repo-synapse/` to `.git/info/exclude`, also with `--no-install`; if the exclude file cannot be written, it warns and goes on | `events.jsonl` lists the repo and must not end up in a commit; a read-only exclude must not leave hooks half installed |
| I15 | The record of the `bashEditDiffEnabled` change lives outside the repo, in `$CLAUDE_CONFIG_DIR/repo-synapse/` (`bash-diff.json` with the viewers that use it, repo and PID, and `settings.json.bak`; mode 0600). It is reverted when the last live viewer exits; if that fails (invalid JSON, write error) the record stays and the next `start` or `uninstall` retries | The copy of the user settings may hold tokens and must not stay in the repo; the key is global and shared by viewers of different repos |
| I16 | The watcher reports `move` when it pairs an unlink with an add: same inode, same path with different case, or same name / only pair in the batch if the entry was not just born (birthtime older than 1 s). An unpaired unlink waits 200 ms before going out, and waiting child unlinks are dropped if the parent's `unlinkDir` arrives later | `fs.watch` has no renames; without this an `mv` showed as a delete plus a create. FSEvents sometimes delivers the children of an `rm -r` one batch before the directory |
| I17 | The watcher's `lstat` checks the exact case of each segment with `readdir` | On APFS, after `mv Foo.ts foo.ts`, `lstat('Foo.ts')` still works and left a ghost node |
| I18 | Hook and watcher are deduplicated per Bash window, not with a fixed 2 s. What the watcher already showed during the window of a `tool_use_id` is removed from that Bash's Post, but only if it showed the same state (exists or no longer exists); a new directory does not cover the files created inside it later. What the hook showed suppresses the watcher afterwards | A long command repeated events once the 2 s ran out; and a file created and deleted by the same command lost the delete when only the path was compared |
| I19 | A Bash `rm`/`mv` without `bashEditDiff` does not touch the tree: the watcher updates it. A glob, the roots of `find -delete` and `rm -rf .` become `bash`, not `delete`. `mv` gives `paths` with the new paths and `fromPaths` with the old ones, aligned | The command line is a guess; the disk says what happened |
| I20 | Attribution to a window uses the time the watcher saw the change (`DiskChange.ts`), not the time it is processed. Closed windows are kept for 5 s more | A late flush misattributed external changes seen before the `PreToolUse` |
| I21 | Outside git, hooks do not add paths under `DEFAULT_EXCLUDES` to the index; the watcher still reports the removal of an excluded path the index knows | Consistent with the initial scan; without this `build/` entered the tree and never left |
| I22 | During the first 10 s after startup, a change to `.claude/settings.local.json` updates the tree without producing an event; its atomic temp file never produces an event | It is the hook install done by `start` itself, not an external change |
| I23 | The lock stores `pid`, `startedAt` and `cmd` (the CLI script). It is stale if the PID died or if the process started more than 5 s after `startedAt` (`ps -o etime`) and its command line does not name `cmd`. The live-lock refusal says which file to delete | A PID reused after a reboot blocked `start` forever. `cmd` keeps a wall clock jump (NTP, a resumed VM) from making a live owner look stale |
| I24 | The lock is created with a temp file + hard link (it is never seen empty). Taking over a stale lock is serialized with an exclusive `lock.takeover` guard: its holder compares the content and only then deletes; a fresh lock is never moved. A guard from a dead process or older than 10 s is cleaned up | With three or more racing `start`, renaming the lock before checking it let two of them win |
| I25 | `install` refuses only if a live `start` runs on the repo and its install manifest exists | Rewriting the viewer's hooks would point them at another port; with `start --no-install` there is nothing to protect |
| I26 | Real smoke test (2026-09-30, `claude -p` + the `DEMO.md` prompt on the demo repo): 44 events, every step visible, hook -> WS latency of 0-5 ms, 60 fps (Apple M4), `~/.claude/settings.json` byte for byte identical after `Ctrl+C` | Checks the acceptance criteria with a real session |
| I27 | Accepted limitation: with `bashEditDiff` off, `rm x; cp -p y z` can look like a move (the watcher pairs by name when `cp -p` keeps the timestamps) | Rare case; with `bashEditDiff` on (the default) it does not apply |

## Round 3: Neurons (2026-10-03)

| # | Decision | Reason |
|---|---|---|
| I28 | The product is called Neurons. Package `neurons-cli` 0.2.0 (0.3.0 since round 4) with the bins `neu` and `neurons`; per-repo folder `.neurons/`; hook marker `?src=neurons`; `bashEditDiffEnabled` record in `$CLAUDE_CONFIG_DIR/neurons/`; variables `NEURONS_ALLOWED_ORIGINS` and `NEURONS_DEBUG`. The old names are recognized and cleaned up: `start`, `install` and `uninstall` remove the `?src=repo-synapse` hooks (by exact URL, as in I2), undo a leftover `.repo-synapse/install.json` the way the previous version would have, and move the old `bash-diff.json` record (or merge it with a new one), dropping owners whose PID is dead. `.repo-synapse/events.jsonl` is kept and `replay` uses it when the new one is missing. The `REPO_SYNAPSE_*` variables keep working. A backup of `settings.local.json` that contains our own hooks, old or new, is never restored byte for byte: the clean JSON is written instead | A short name to type every day. Whoever used the previous version must not be left with orphan hooks that print `hook error`, nor lose their logs. Blindly restoring a backup taken with old hooks inside installed them again |
| I29 | `neu` with no arguments is `neu start` in the current folder, and `neu <folder>` is `neu start <folder>` if the folder exists and is not named like a command. Command names win over folders with the same name. An unknown word fails with a suggestion (`Did you mean "neu stop"?`) and, if it looks like a path, says the folder does not exist | Daily use is `cd my-repo && neu`. Commands always winning means that creating a `stop` folder never changes what `neu stop` does |
| I30 | `start`, `install`, `uninstall`, `replay` (with a folder), `doctor`, `stop` and `open` go up to `git rev-parse --show-toplevel` (through `execFile`, no shell) and say so when the folder changed. Outside git, `start` warns that the tree is built by walking the folder | Opening the viewer from `src/` left a partial tree and the hooks in `src/.claude/`, far from where Claude Code is usually opened. The notice keeps the folder change from being a surprise |
| I31 | On startup, `start` looks for Claude Code sessions open inside the repo: on macOS, candidates come from `ps -axo pid=,ppid=,args=` (argv[0] `claude*`, or node/bun running the Claude Code script) and their cwd from `lsof -nP -a -p <pids> -d cwd -Fpn`; on Linux, from `/proc`. Its own process tree (the CLI, its ancestors and its descendants) is excluded and paths are compared with symlinks resolved. With sessions it names their PIDs, says they pick up the hooks live and offers a restart (`/exit` and `claude --continue`) only as plan B for older versions (since I50: `/reload-plugins` first, then the restart); with no sessions it asks to open Claude Code; if detection fails, it says both things in a generic notice. No signal is ever sent to those processes | Naming the open sessions removes the doubt about whether the viewer sees them. I9 is verified: a session opened before the viewer picks up the hooks without a restart. `lsof -c claude` is not enough because the native build runs from `versions/<version>` and the kernel's process name is the version number |
| I32 | Viewer registry in `~/.neurons/viewers/<pid>.json` (`NEURONS_HOME` changes the base), with `{pid, repo, port, url, startedAt, cmd}`. `start` writes it when it starts listening and deletes it on exit. Every read prunes dead PIDs, reused PIDs (same rules as the lock, I23), corrupt files and files whose name does not match their PID. `neu ls`, `neu open` and `neu stop` work on top of it | `ls` has to see viewers of every repo, so it cannot live in each repo's `.neurons/`. It does not go in `$CLAUDE_CONFIG_DIR` either: someone can use a different `CLAUDE_CONFIG_DIR` per terminal and `neu ls` must still list everything |
| I33 | `neu stop` sends `SIGTERM` and waits up to 8 s; if the viewer does not exit it says so and does not kill it. If it did not exit, `--force` sends `SIGKILL` and then does the cleanup the viewer did not get to do: removes its hooks, reverts `bashEditDiffEnabled`, deletes the lock and the registry entry. A signal is only sent after confirming with `ps` that the command line runs the registered script, and that is confirmed again right before the `SIGKILL`. With no registry entry, `stop` uses the repo lock, only if it is live and records which script took it | Real Claude Code sessions run on the same machine: a reused PID must never get a signal. A `SIGTERM` shutdown leaves everything byte for byte as it was; `SIGKILL` is the exception and that is why it brings the cleanup along |
| I34 | Session tint: every main session gets a soft hue from a palette of 8 (clay, sage, lavender, rose, olive, periwinkle, straw, mauve), in order of first appearance, and the palette wraps after the eighth. The tint shows only with two or more active sessions; a session counts while it has not ended or for 10 min after its last event (in replay, by the log's clock). It shows as a thin ring around the node, a border on the feed rows, a dot in the session filter and chips in the "Sessions" line that filter when tapped. Subagent events keep their halo and external changes their gray, with no ring | Tell sessions apart without filtering. With a single session it adds nothing and the view stays as before. The muted hues do not compete with the action colors or the saturated subagent halos, and first-appearance order makes a reload repeat the same colors |
| I35 | Viewer identity before sending a signal: the lock and the registry also store `command`, the `ps` line the viewer saw of itself at startup, and it is compared exactly (without it, `cmd` must appear as a whole argument, not as the prefix of another path). The process must also have started before `startedAt` plus 5 s; for signals the clock-jump exception of I23 does not apply, it is kept only to decide whether a lock is live. `stop` with the lock as fallback discards a PID that the registry records for another repo | `/usr/local/bin/neutron` contained `/usr/local/bin/neu` and got the signal. A stale lock whose PID was reused by another repo's viewer made `neu stop A` close B. `process.argv[1]` is absolute but `ps` shows the path as typed (`tsx src/cli.ts`), and `stop` refused to close those viewers. A legitimate viewer after a big clock jump may become impossible to close with `stop`: it closes with `Ctrl+C`, and that is preferred over a signal to a foreign process |
| I36 | Coexistence with a repo-synapse viewer that started later: while its lock is live, `uninstall` and the `neu` cleanup do not touch its `?src=repo-synapse` hooks or its `install.json`, and the `bashEditDiffEnabled` record in `$CLAUDE_CONFIG_DIR/repo-synapse/` is used in place (the new viewers register as owners) instead of being moved. It is moved once no old owner is alive | The old version only looks at its own lock, so it can start next to `neu`. Removing its hooks cuts its events, and moving its record leaves its exit with nothing to revert, so `bashEditDiffEnabled` stays on |
| I37 | Tint: a session that ended with `/clear` (`SessionEnd` reason `clear`) stops counting as active at once. In replay, every `tree` line (a new server start in the same log) ends the sessions that were still open. A session pulse weaker than the glow the node already has does not replace it: it only adds the ring, and never over a subagent halo | `/clear` goes on in the same window with another `session_id`, and lit the multi-session tint for 10 min. Closing the viewer does not record the end of the open sessions, which stayed active forever in replay. Replacing the glow erased the subagent halo and the blink of a failure |
| I38 | Claude Code subagent worktrees (`Agent` with isolation `"worktree"`, which runs `git worktree add <repo>/.claude/worktrees/agent-<id>`) never enter the tree: everything under `.claude/worktrees/` is excluded from the initial scan, the watcher (with and without git, whether `.gitignore` ignores it or not) and the index, and the watcher drops it before attribution. A hook with a path `<repo>/.claude/worktrees/<name>/rest` is rewritten to `rest` (the same file in the main repo) and the event carries `worktree: "<name>"`. The mark goes by path, not by command: an `rm` or `mv` that mixes main repo and worktree paths is split into one event per tree, and an `mv` across the border is a `delete` on one side and a `create` on the other, never a `move`. Events with `worktree` are shown but neither add nor remove nodes nor take part in watcher deduplication. The view lights the equivalent node if it exists, and otherwise (a file created only in the worktree) its deepest ancestor; the feed row carries the `worktree` label. A git worktree outside the repo (for example `~/orca/workspaces/...`) still goes to `outsideRepo` | Live test: a subagent's `git worktree add` produced about 110 watcher `create` events, doubled the network (225 nodes instead of about 110) and attributed them to another session that had an unrelated Bash open. The checkout is a copy of the same repo: showing it as new files is false, and rewriting the path shows which part of the project the subagent is touching |
| I39 | `UserPromptSubmit` also carries prompts written by Claude Code, not the person: when a background subagent ends it injects `<task-notification> <task-id>… <tool-use-id>…`. If the prompt (without leading spaces) opens with an XML-like tag (`^<[a-z][a-z0-9_-]*>`), the `detail` of the `turn_start` is "background task notification" for `<task-notification>` and "system notification" for any other, never the text. Claude Code's tags always have `-` or `_` in the name, so only those count: a typed prompt that opens with `<div>` or `<Button>` is shown. In a typed prompt, whole tags that remain (`<x>`, `</x>`, `<x a="1">`, `<x/>`) are removed before truncating to 120 characters; an `a<b` or `if a<b and c>d` is not a tag and stays | The feed showed a "turn" row with the raw tags and internal ids. Removing tags can eat a `<Button>` or `<div>` typed on purpose (the rest of the text stays), and a typed prompt that opens with a hyphenated custom element (`<my-button>`) shows as "system notification"; both cases are rare |

| I42 | Timeline view, next to 3D and 2D: a Canvas 2D swimlane with time on X and one row per file (also search folders, outside paths, skills and MCP tools) in order of first touch, grouped by folder; one mark per event and path; top bands for prompt turns (up to 2 lanes) and subagent lifetimes (up to 4 lanes). The data model (`web/src/timelineModel.ts`) is pure and unit tested | The 3D network shows where the agent is now; the Timeline shows the order and the rhythm. | I43 | Tool tracking. Every tool event carries `tool: {kind: 'builtin' \| 'mcp' \| 'skill', name, server?}`. The `Skill` tool becomes action `skill` (`#fb923c`, `paths: []`, `detail` = skill name, not in `FILE_ACTIONS`). An `mcp__<server>__<tool>` tool becomes action `mcp` (`#2dd4bf`, in `FILE_ACTIONS`, paths from `tool_input.file_path` or `path`, `detail` = `server/tool`); the server name comes from `mcp_server.name` when the payload has it, otherwise from the tool name. | I44 | Command detail privacy. Bash events carry `command`: at most 2,000 characters with newlines kept, heredoc bodies cut (also the common `"$(cat <<'EOF' … EOF)"` form), quoted literals redacted to `…` in statements that write files or run inline code (also across lines), here-strings redacted, `$'..'` literals handled, and an unterminated literal cut at its opening quote. Privacy tests cover multi-line heredocs and commit bodies, multi-line `echo`, MCP payloads and the single-line `error`. Since round 4 (I51) the write / inline-code decision is made once for the whole command, `detail` is the first line of `command`, and secret-looking values are redacted in every command | The detail drawer needs the whole command to be useful, but a command can carry the content it writes. Cutting and redacting at the source keeps file content out of the browser and `events.jsonl`, as for `detail` |
| I45 | Floating "now" stream at the bottom left of the graph: at most 6 lines like a live chat ("Editing src/api/user.ts"), newest at the bottom, each one leaving after 8 s. A Pre and its Post (same `toolUseId`) share one line. Hover pauses the clock; a click opens the event in the detail drawer | The feed in the panel is a log; the stream answers "what is it doing right now" without looking away from the graph |
