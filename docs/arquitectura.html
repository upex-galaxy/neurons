repo-synapse · arquitectura

Cómo se enciende la red

repo-synapse es un comando de terminal. Levanta un servidor en tu máquina, le pide a Claude Code que le avise de cada cosa que hace y dibuja tu repositorio como una red de nodos que se ilumina en vivo. Este documento muestra cómo encajan las piezas.

Capítulo 1 · Arquitectura

Vista general

Hay dos fuentes de información. La principal son los hooks HTTP de Claude Code: cada vez que Claude decide usar una herramienta, y cada vez que termina, Claude Code hace un POST con un JSON que describe la acción. La segunda es un watcher del sistema de archivos, que ve los cambios de disco que ningún hook describe con precisión, como un rm dentro de un comando Bash.

Las dos llegan al mismo servidor local. Ahí cada aviso se convierte en un evento chico (acción, fase, rutas) que viaja por WebSocket hasta el navegador y queda guardado en un log para el replay.

El servidor responde 204 vacío apenas recibe el cuerpo, antes de procesarlo. Claude Code espera alrededor de 1 ms (con un tope de 2 s) y nunca recibe algo que pueda interpretar como una decisión.

Capítulo 2 · Ciclo de vida

Qué pasa al correr start

Los hooks solo existen mientras el visor está abierto. Si Claude Code tuviera un hook HTTP apuntando a un servidor apagado, cada herramienta imprimiría un hook error en rojo. Por eso start los escribe al arrancar y los quita al cerrar.

# terminal 1
repo-synapse start ~/mi-repo
# terminal 2, después de arrancar el visor
cd ~/mi-repo && claude
# al terminar: Ctrl+C en la terminal 1

Capítulo 3 · Secuencia

Un Read de punta a punta

Cada herramienta produce dos avisos: PreToolUse cuando Claude decidió usarla y PostToolUse cuando terminó. En la red se ven como dos pulsos: uno tenue (intención) y uno completo (hecho). Los tiempos salen de sesiones reales con Claude Code 2.1.285 en macOS (captura de la fase 0 y prueba de humo).

El payload de un Read trae el contenido completo del archivo. El normalizador lo descarta: al navegador y al log solo llegan rutas y metadatos.

Capítulo 4 · Decisión

¿Fue Claude o fuiste vos?

No existe una herramienta de borrado. Claude borra y mueve con Bash (rm, git mv), y el hook solo trae el texto del comando. Para saber quién cambió un archivo, el servidor abre una ventana por cada comando Bash, desde su PreToolUse hasta que termina (PostToolUse, un fallo o un permiso denegado, más 600 ms de gracia), y cruza cada cambio de disco con esas ventanas.

Si Claude Code tiene activado bashEditDiffEnabled, el PostToolUse de Bash ya trae la lista exacta de archivos creados, borrados y modificados. Hook y watcher se deduplican: el que llega primero enciende el cambio y el otro no lo repite.

Capítulo 5 · La red

Del árbol a la red

El árbol sale de git ls-files --cached --others --exclude-standard: todo lo versionado más lo nuevo que no está ignorado. Cada carpeta y cada archivo es un nodo, y cada línea une una carpeta con lo que contiene. Todo lo que ignora .gitignore queda afuera. Fuera de git se recorre el disco salteando node_modules, dist y build, y en los dos casos el escaneo se corta en 50.000 archivos.

Cuando llega un evento sobre src/api/user.ts, la luz recorre la ruta desde la raíz, un salto cada 80 ms, y el nodo destino brilla y se apaga en unos 3,5 segundos.

Subagentes

Los eventos de un subagente traen agent_id. Cada uno recibe un tono propio y pinta un halo alrededor de los nodos que toca, así se ve qué explora cada agente en paralelo.

Fuera del repo

Tu ~/.claude/CLAUDE.md, las skills o /tmp aparecen como satélites en un cúmulo aparte, unido a un hub "fuera del repo".

Repos grandes

Con más de 1.500 nodos visibles las carpetas se colapsan. Una carpeta colapsada se abre sola cuando llega un evento sobre algo que contiene (también los externos, si están visibles), y se vuelve a cerrar si la red supera unos 1.950 nodos.

Capítulo 6 · Huella

Qué toca en tu máquina

Lo que start cambia en la configuración de Claude (settings.local.json y bashEditDiffEnabled) tiene backup y se revierte al cerrar; si no hubo otros cambios, esos archivos quedan idénticos byte a byte. .git/info/exclude y .repo-synapse/events.jsonl quedan a propósito.

ArchivoQué hace startAl cerrar
<repo>/.claude/settings.local.jsonAgrega 14 hooks HTTP a http://127.0.0.1:<puerto>/hook?src=repo-synapse, con timeout: 2. Respeta los hooks que ya teníasQuita solo sus entradas. Si el archivo no existía, lo borra
~/.claude/settings.jsonActiva bashEditDiffEnabled si estaba apagado. No lo toca con --no-bash-diff ni con --no-install, y no crea el archivo si no existe o no es JSON válido. Respeta $CLAUDE_CONFIG_DIRLo devuelve a su valor anterior cuando cierra el último visor
~/.claude/repo-synapse/Backup de settings.json y registro de los visores que usan bashEditDiffEnabled (modo 0600)Se borra al revertir la clave
<repo>/.repo-synapse/Log events.jsonl (se agrega a lo que ya había), lock, manifiesto de instalación y backup settings.local.json.bakQueda el log, para el replay; el backup se borra al desinstalar
<repo>/.git/info/excludeAgrega /.claude/settings.local.json y /.repo-synapse/ si git no los ignoraba (en cada start, también con --no-install)Queda; no se versiona y evita ruido en git status

Si el proceso muere de golpe, repo-synapse uninstall <repo> deshace la instalación, y el próximo start limpia por sí solo lo que haya quedado.
