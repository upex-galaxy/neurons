Neurons · architecture

How the network lights up

Neurons is a terminal command (neu). It starts a server on your machine, asks Claude Code to report everything it does and draws your repository as a network of nodes that lights up live. This page shows how the pieces fit together.

Chapter 1 · Architecture

Overview

There are two sources of information. The main one is Claude Code's HTTP hooks: every time Claude decides to use a tool, and every time it finishes, Claude Code sends a POST with a JSON body that describes the action. The second is a file system watcher, which sees the disk changes no hook describes precisely, like an rm inside a Bash command.

Both reach the same local server. There each report becomes a small event (action, phase, paths and, for a tool, which tool it was) that travels over WebSocket to the browser and is kept in a log for replay.

The server answers an empty 204 as soon as it has the body, before processing it. Claude Code waits about 1 ms (with a 2 s cap) and never gets anything it could read as a decision.

What the server serves

RouteWhat it is
GET /The web app: the 3D, 2D and Timeline views, the side panel and the live stream
POST /hookClaude Code's hooks. Empty 204, sent before the payload is processed
GET /wsThe event stream: hello with the tree and the latest events, then every event live. Only from the server's own origin, plus NEURONS_ALLOWED_ORIGINS

GET /architectureThis page (architecture.html)
GET /docs/*Any file of the built docs; /i18n/* and /img/* too, for the pages' dictionaries and images

Chapter 2 · Lifecycle

What happens when you run start

The hooks only exist while the viewer is open. If Claude Code had an HTTP hook pointing at a server that is down, every tool would print a red hook error. That is why start writes them when it starts and removes them when it closes. A Claude Code session that was already open picks them up live, with no restart (verified with Claude Code 2.1.288).

# terminal 1
cd ~/my-repo && neu
# terminal 2 (a session that is already open works too)
cd ~/my-repo && claude
# when you are done: Ctrl+C in terminal 1

Chapter 3 · Sequence

One Read, end to end

Every tool produces two reports: PreToolUse when Claude decided to use it and PostToolUse when it finished. On the network they show as two pulses: a faint one (intent) and a full one (done). The timings come from real sessions with Claude Code 2.1.285 on macOS (the phase 0 capture and the smoke test).

The payload of a Read carries the whole file content. The normalizer drops it: only paths and metadata reach the browser and the log.

What an event carries

Besides the action and the paths, a tool event says which tool it was and carries a few short details. The detail drawer, the Timeline and the Tools section of the panel show them. None of them is file content.

FieldWhat it holds
toolKind (builtin, mcp or skill), name and, for MCP, the server: mcp__github__search_code becomes server github, tool search_code
commandBash: the command, up to 2,000 characters. Heredoc bodies are cut, and when the command writes files or runs inline code (>, tee, sed -i, python -c...) its quoted literals become …
cliBash: the programs it runs (git, npm, gh...), at most 8, skipping wrappers, variable assignments and builtins like cd
descriptionBash and Agent: Claude's own explanation (tool_input.description), up to 300 characters
patternSearches: the grep/rg pattern, the find -name glob or the Glob/Grep pattern
durationMs, errorPost and failure: how long the tool took and, on failure, the first line of the error (up to 200 characters)

Chapter 4 · Decision

Was it Claude or was it you?

There is no delete tool. Claude deletes and moves with Bash (rm, git mv), and the hook only carries the command text. To know who changed a file, the server opens a window for every Bash command, from its PreToolUse until it ends (PostToolUse, a failure or a denied permission, plus 600 ms of grace), and matches every disk change against those windows.

If Claude Code has bashEditDiffEnabled on, the Bash PostToolUse already carries the exact list of created, deleted and modified files. Hook and watcher are deduplicated: whichever arrives first lights the change and the other does not repeat it.

Chapter 5 · The network

From tree to network

The tree comes from git ls-files --cached --others --exclude-standard: everything tracked plus anything new that is not ignored. Every folder and every file is a node, and every line joins a folder with what it contains. Whatever .gitignore ignores stays out. Outside git the disk is walked skipping node_modules, dist and build, and in both cases the scan stops at 50,000 files.

When an event about src/api/user.ts arrives, the light runs along the path from the root, one hop every 80 ms, and the target node glows and fades in about 3.5 seconds. The links it crossed stay tinted in the action color and fade slowly: 5 s, or 7 s for edits, creations and deletes.

Subagents

Events from a subagent carry agent_id. Each one gets its own hue and paints a halo around the nodes it touches, so you can see what each agent explores in parallel.

Outside the repo

Your ~/.claude/CLAUDE.md, skills or /tmp show up as satellites in a separate cluster, joined to an "outside the repo" hub.

Large repos

With more than 1,500 visible nodes the folders collapse. A collapsed folder opens on its own when an event arrives about something inside it (external ones too, if they are visible), and closes again if the network goes past about 1,950 nodes.

Timeline

A third view next to 3D and 2D: one row per file in order of first touch, grouped by folder, with time on the X axis (long pauses shortened) and bands for prompt turns and subagents. It draws only what is on screen.

Live stream

At the bottom left of the graph, the last 6 actions as short lines ("Editing src/api/user.ts"). A Pre and its Post share one line; each line fades after 8 s, hovering pauses it and a click opens the event in the detail drawer.

Panel and tools

The side panel resizes by dragging its left edge (or with ←/→ when it has focus), between 280 and 720 px, and remembers its width. Its Tools section counts skills, MCP servers and tools, CLI programs and Claude's built-in tools.

Chapter 6 · Footprint

What it touches on your machine

What start changes in the Claude configuration (settings.local.json and bashEditDiffEnabled) has a backup and is reverted on close; if nothing else changed, those files end up byte for byte identical. .git/info/exclude and .neurons/events.jsonl stay on purpose.

FileWhat start doesOn close
<repo>/.claude/settings.local.jsonAdds 14 HTTP hooks to http://127.0.0.1:<port>/hook?src=neurons, with timeout: 2. Keeps the hooks you already hadRemoves only its own entries. If the file did not exist, it deletes it
~/.claude/settings.jsonTurns on bashEditDiffEnabled if it was off. Leaves it alone with --no-bash-diff or --no-install, and does not create the file if it is missing or is not valid JSON. Honors $CLAUDE_CONFIG_DIRPuts it back to its previous value when the last viewer closes
~/.claude/neurons/Backup of settings.json and the record of the viewers that use bashEditDiffEnabled (mode 0600)Deleted when the key is reverted
<repo>/.neurons/The events.jsonl log (appended to), the lock, the install manifest and the settings.local.json.bak backupThe log stays, for replay; the backup is deleted on uninstall
<repo>/.git/info/excludeAdds /.claude/settings.local.json and /.neurons/ if git did not ignore them (on every start, also with --no-install)Stays; it is not versioned and keeps git status quiet
~/.neurons/viewers/<pid>.jsonRecords the viewer (repo, port, URL, PID) so that neu ls, neu open and neu stop can find it. Honors $NEURONS_HOMEDeleted

If the process dies abruptly, neu uninstall <repo> undoes the install, and the next start cleans up whatever was left on its own. On Windows a signal ends the viewer without letting it clean up, so neu stop does that cleanup itself.
